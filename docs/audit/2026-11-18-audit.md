# MOOSE framework audit (2026-11-18)

Scope: core traits, params and smoothing, the CLAP wrapper (activate / reset /
process / state), VST3 state, prepare and process (Rust side and the C++ shim),
AU output-event callbacks, `PluginCell`, `SnapshotSlot`, the transport seqlock,
the static and hot shells. Not yet read: the AU v2 shim render path, the
hot-reload loader internals, GUI crates, `cargo-moose`. Nothing was built or
run; findings come from reading the code. nih-plug (f36931f) and JUCE 8.0.7
were compared from source.

## Architecture in one paragraph

Authors write a stateless `PluginLogic` description, a `DspState`, and an
atomic `Params` struct. `moose::plugin!` builds a static or hot-reload shell
that implements `PluginRuntime`; the CLAP, VST3 and AU wrappers consume that
and route `process` through `chunked_process`, which splits blocks at
automation points. The plugin lives in `PluginCell`, an ownership flag with no
lock that trusts the host not to overlap `process` with lifecycle calls. Loads
go through a one-slot queue the audio thread drains at the top of the next
block. Saves read a snapshot the audio thread publishes after each block.

Good: the audio thread never blocks; panics are caught at every C ABI
boundary; scratch is pre-sized at activate; `rt-paranoid` allocation checks;
NaN-guarded parameter writes; hot reload that keeps DSP state; sample-accurate
splitting on by default; full MIDI 2 / UMP.

Bad: very large files (CLAP 7.6k lines, VST3 4.7k, AU 4.1k, derive 4.2k,
`EventList` 2.6k); a hand-written VST3 COM ABI with no SDK; state contracts
that depend on whether the audio thread happens to run.

## Findings, most severe first

1. **Save after load returns stale custom state (CLAP, VST3).** While active,
   a load is only queued (`moose-clap/src/lib.rs` `state_load`,
   `moose-vst3/src/lib.rs` `apply_host_state`). If the host is not calling
   `process` (CLAP sleep, Cubase suspend, the gap between activate and
   start_processing), a save writes new params with old custom state. The
   editor's `state_changed` fires before the state is applied.
2. **Audio-thread allocation every block by default.** The default
   `snapshot_into` calls `save_state` (allocates a `Vec`); without
   `snapshot_version` it runs every block (`moose-plugin/src/lib.rs`,
   `moose-loader/src/static_shell.rs` `publish_snapshot_with`).
3. **`reset` runs on the audio thread but is documented "allocate freely".**
   Called from activate, CLAP `reset` (audio thread per spec), VST3
   `setProcessing(false)` (audio thread in some hosts).
4. **Silent, torn loads.** Host gets success before `load_state` runs;
   `apply_state` drops the error in release. `#[persist]` fields are applied on
   the host thread, params and extra later on the audio thread. The popped
   state is freed on the audio thread.
5. **No latch after a panic in `process`.** The plugin is re-entered every
   block in a possibly corrupt state, and `eprintln!` runs on the audio thread
   each time (`moose-core/src/wrapper.rs` `run_audio_block_with`).
6. **`f64` prelude narrows smoothed values through `f32`**
   (`moose-params/src/types.rs` `FloatParamReadF64`).
7. **Smoother `next()` and `next_into()` disagree** on snapping to target
   despite docs saying they match; smoother state is atomics in shared params,
   so every sample pays atomic loads and stores.
8. **`PluginCell::enter` asserts instead of waiting.** An overlapping host
   call panics; the callback catches it and the call is silently dropped.
9. **VST3 shim limits.** 512 parameter points per block in a fixed stack
   array, excess dropped silently; 32 channels per direction; global
   descriptor (one class per binary); hand-rolled ABI.
10. **O(n²) on the audio thread.** AU `cb_output_*_at` use
    `filter().nth(index)` per index; the chunker's `.skip()` on
    `EventList::iter()` (a `FilterMap`) is O(n) per sub-block.
11. **Dev-only unmangled exports in release binaries:** the hot-reload ABI
    from `export_plugin!` and `__moose_screenshot`.
12. **CLAP modulation is passed through but never applied** to the parameter
    value for `MODULATABLE` params.
13. Minor: transport seqlock is formally a data race (volatile mitigation);
    `SendPtr<T>` is `Send + Sync` for any `T`; unnecessary `unsafe impl Send`
    (e.g. `StaticShell`); every param write bumps a process-wide `EDIT_EPOCH`.

## Comparison

| | nih-plug | JUCE 8.0.7 | MOOSE |
|---|---|---|---|
| Format SDKs | clap-sys, vst3-sys | Steinberg SDK, AudioUnitSDK, clap-juce | hand-rolled VST3 C++, C AU v2 shim |
| Load while processing | main thread under mutex, reports errors | main thread, user locks, can't report | queued, early success, errors dropped |
| Save | main thread, live values | main thread | audio-thread snapshot, can be stale |
| Audio-thread blocking | can stall on mutex | can stall on callback lock | never |
| Panic in process | aborts host | terminates host | caught, no latch |
| Automation splitting | opt-in, no minimum | none (VST3 last point) | default, 32-sample minimum |
| Hot reload | no | no | yes |
| AUv3 | no | yes | no |
